# SDK 接入记录

业务页面不提供检查报告或实验入口；本文仅记录工具包缺口与页面适配。

## 已发现的问题及页面适配

### 1. Modify.revoke 跨要素撤销错误（已复现）

当前安装版本为 `openlayers-map-kit@0.1.0-beta.1`。

最小复现：

1. 创建同一 VectorLayer 中的点 A `[0, 0]` 和点 B `[10, 10]`。
2. 创建 `new Modify({ layer })`。
3. 将 A 改为 `[1, 1]`，触发 modifyend。
4. 将 B 改为 `[20, 20]`，触发 modifyend。
5. 调用 `revoke()`。

预期：A 保持 `[1, 1]`，B 恢复 `[10, 10]`。实际：B 仍为 `[20, 20]`。

源码 `src/module/interaction/Modify/index.ts` 的 modifyend 只快照当次修改的要素，revoke 恢复上一条记录的要素，未恢复本次修改的其他要素。页面保留完整图层快照，在调用 SDK revoke 后补偿恢复；工具包修复后可移除这一补偿。

浏览器也已通过“移动点 → 移动面节点 → 撤销”复现，并验证页面补偿能恢复面节点、保留点的前一次修改；恢复初始可还原两者。

### 2. LayerGroup 缺少父级状态接口（能力缺口）

目前公开 API 管理图层集合，没有父级显隐、透明度和嵌套继承。页面保存子层偏好并合成实际状态。可考虑工具包提供统一父级状态接口。

### 3. HeatmapLayer 缺少参数设置包装（能力缺口）

半径和模糊度通过 `getLayer()` 调用 OpenLayers `setRadius` / `setBlur`。可考虑包装这些常用方法，减少业务访问原生对象。

### 4. 热力图 WebGL 释放顺序（底层生命周期问题）

OpenLayers 10.6.1 的热力图先从地图移除再 dispose，在已生成缓冲区时可能出现 `helper` 已释放、读取 `deleteBuffer` 失败。浏览器热更新过程中已观察到该错误。页面在移除热力图前释放原生 renderer，再移除/释放图层和外部 VectorSource；产品页面在卸载与移除热力图时使用这一释放顺序。

建议工具包核查 BaseLayer.dispose 与 WebGL 图层生命周期，单独覆盖“已渲染 → 移除 → 释放”和页面卸载场景。此问题不直接归因于业务页面或网络服务。
